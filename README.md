# Champion–Challenger Model Comparison with Hugging Face and MLflow

Compares two pre-trained sentiment classifiers on a labelled evaluation set, registers both in the MLflow Model Registry, assigns `champion` / `challenger` aliases using a pre-defined decision rule, and serves predictions through the champion alias.

## 1. Task and Models

**Task:** Binary sentiment classification (positive / negative).

| Dataset | File | Description |
|---|---|---|
| Evaluation | `data/eval_inputs.csv` | 100 labelled examples. Both models are evaluated on the same saved inputs and labels. |
| New predictions | `data/new_data.csv` | 10 unlabelled examples used for inference after model registration. |

> The evaluation dataset is custom-created. It is **not** the official SST-2 validation or test split.

| Role | Hugging Face model ID |
|---|---|
| Model A — Initial Champion | `distilbert-base-uncased-finetuned-sst-2-english` |
| Model B — Challenger | `textattack/bert-base-uncased-SST-2` |

## 3. How to Run

Run all commands from the project root directory using **Windows PowerShell**.

### 3.1 Create and activate a virtual environment

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3.2 Install dependencies

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3.3 Start the MLflow tracking server

Open a **second terminal**, activate the same virtual environment, and run:

```powershell
.\venv\Scripts\Activate.ps1
python -m mlflow server --host 127.0.0.1 --port 5000
```

Keep this terminal running. The MLflow UI is available at <http://127.0.0.1:5000>.

### 3.4 Evaluate both models

Return to the project terminal and run:

```powershell
python evaluate.py
```

This evaluates both models on `data/eval_inputs.csv`, logs parameters, metrics and model artifacts to MLflow, and saves evaluation outputs in `outputs/`.

### 3.5 Register the models and assign aliases

```powershell
python register_champion.py
```

This registers both models under the name `sentiment-classifier` and assigns the `champion` and `challenger` aliases according to the decision rule in [Section 4](#4-champion-selection-rule).

### 3.6 Predict using the champion alias

```powershell
python predict_from_mlflow.py
```

The script loads the model through the MLflow URI:

```
models:/sentiment-classifier@champion
```

It displays the champion alias, registered model version, Hugging Face model ID and 10 predictions, and saves the results to `outputs/new_data_predictions.csv`.

## 4. Champion Selection Rule

The decision rule was defined **before** the final evaluation run and was not changed after inspecting the results.

| Component | Rule |
|---|---|
| Primary metric | Accuracy — higher is better |
| Minimum improvement margin | The challenger must improve accuracy by at least **0.01** (one percentage point) to replace the current champion |
| Tie-breaker | If the accuracy improvement is below 0.01, the model with lower average inference latency is preferred |
| Latency direction | Lower average inference latency is better |

## 5. Evaluation Results

Both models were evaluated on the same 100 labelled examples using CPU inference.

| Metric | Model A — DistilBERT | Model B — TextAttack BERT | Difference (B − A) |
|---|---:|---:|---:|
| Accuracy | 0.9700 | **0.9900** | +0.0200 |
| Precision | 0.9796 | **1.0000** | +0.0204 |
| Recall | 0.9600 | **0.9800** | +0.0200 |
| F1-score | 0.9697 | **0.9899** | +0.0202 |
| Average latency (ms) | **12.8654** | 26.8266 | +13.9612 |
| Total inference time (s) | **1.2865** | 2.6827 | +1.3962 |

**Selected Champion: Model B — `textattack/bert-base-uncased-SST-2`**

## 6. Decision

Model B is selected as the champion. It achieved an accuracy of 0.99 versus 0.97 for Model A. The absolute improvement of 0.02 (two percentage points) exceeds the pre-defined minimum margin of 0.01. Model B also produced higher precision, recall and F1-score on this evaluation set.

**Latency trade-off:** Model B required approximately 26.83 ms per example, while Model A required approximately 12.87 ms, so Model A was faster in this CPU evaluation. Under the decision rule, the accuracy gain takes priority once it reaches the required margin, so Model B replaces Model A.

**Interpret with caution.** The evaluation contains only 100 examples and uses a custom-created dataset rather than the official SST-2 evaluation split. A two-percentage-point difference on a sample this size may not generalise to other data, and the models may behave differently on text from domains unlike their fine-tuning data. A larger, representative, independently labelled test set and repeated latency measurements would provide stronger evidence.

## 7. Limitations

- The evaluation set contains only 100 labelled examples; results may vary on a larger or different dataset.
- The dataset is custom-created and is not the official SST-2 benchmark split.
- Both models are SST-2 sentiment classifiers; performance may be weaker on text from domains unlike their training data.
- Latency was measured on CPU in a local environment and may differ on other hardware or under different system load.
- Individual predictions can be incorrect even when overall evaluation metrics are high.
